# 初始化可用性修复设计

## 目标

把 `/initialize` 从混合原型改为可用于生产酒店初始化的真实工作流，同时保持员工正式导入、培训历史、CTC/GTC 和 KPI 数据不在本次范围内。

## 根因

当前向导同时使用真实 Repository 与原型 Toast：Logo、职位体系、管理员状态以及多数映射动作没有持久化；工作簿步骤仍调用本地检查接口；完成门槛把硬编码管理员状态和空映射误当成事实。生产库当前没有部门、职位、来源别名或导入批次，因此这些占位逻辑在真实模式下直接暴露。

## 设计

1. **Logo**：第一步复用 `PropertyRepository.uploadLogo`，显示真实当前 Logo、文件校验、上传状态和失败反馈。
2. **职位体系**：新增向导专用职位编辑器，可新增/编辑职位族、正式职位、适用部门与启停状态；至少一个有效职位后才能确认。
3. **生产工作簿检查**：第五步在 Supabase 模式调用 `/api/import/inspect`。文件只写入私有暂存，服务端解析并返回聚合结果，不写员工表。
4. **来源标签暂存**：工作簿检查事务创建或复用部门/职位来源别名，保留批次、工作表和影响行数。已批准别名保持批准结果；新标签默认 deferred。
5. **映射操作**：第六步为每个标签提供真实目标选择和确认面板，支持映射、创建正式节点、运营单元、职位族、外部角色、合并、忽略和延期；结构创建逐项确认。
6. **管理员状态**：新增受限读取接口，通过现有账户、成员资格和角色分配返回当前酒店管理员摘要；向导不再显示合成管理员。
7. **完成门槛**：客户端与 `complete_property_initialization` 使用同一组持久化事实：有效酒店资料、业务规则、至少一个有效部门和职位、已检查员工主工作簿、所有必需标签已处理、活动 Property L&D Manager 和明确步骤确认。

## 安全边界

- 浏览器不接触 service-role；工作簿解析与来源标签暂存只在受限服务端边界执行。
- 导入文件继续使用私有 `property-import-files` bucket。
- 管理员摘要仅对当前属性的授权管理角色返回。
- 所有映射和组织/职位写入继续受既有 RLS 与安全 RPC 约束。
- 本次不写入 `employees`，不导入培训历史或 CTC/GTC。

## 用户体验

每个主要按钮必须产生真实面板、持久化变化、路由或明确错误。保存后重新读取服务器版本；失败不推进步骤。空状态直接解释下一动作，完成检查列出具体阻塞原因。

## 验证

新增应用回归测试和 pgTAP 覆盖来源标签暂存、角色摘要权限、完成门槛和跨酒店隔离；运行干净本地 Supabase reset、全部测试、生产构建、安全扫描、Vercel Preview/Production 验证和真实域名烟雾测试。
