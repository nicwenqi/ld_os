# Position Attribution Batch Initialization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a Hotel L&D Manager resolve many staged source-position labels through a reviewed, atomic batch decision without changing employee facts before the existing final import commit.

**Architecture:** Add a narrow import-batch preview/confirm RPC pair. Confirmation creates official positions or maps labels to one existing position, persists detail `import_source_label_resolutions`, and appends a summary `import_activity_events` record. Existing preview and commit semantics remain unchanged.

**Tech Stack:** React/TypeScript repositories and services, Supabase Postgres RPC/RLS, pgTAP, Node test runner.

## Global Constraints

- Only Hotel L&D Manager may operate the feature.
- No `employees`, Employee Fact Version, D1–D4 fact, or training-fact write occurs at batch attribution.
- Creation is previewed and explicitly confirmed.
- Same-name positions require map-or-create choice.
- Detail source-label evidence plus one aggregate audit event are required.
- No Production migration or deployment is performed during implementation.
